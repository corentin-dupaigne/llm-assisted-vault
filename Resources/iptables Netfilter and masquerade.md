## The layers (bottom to top)

Three distinct things, often conflated:

- **Netfilter** — a framework *in the Linux kernel* that provides **hook points** along the packet's path through the network stack, plus an API (`nf_register_net_hook()`) to register callbacks at them. Netfilter is the engine; it does the actual packet work.
- **iptables / nftables** — userspace *tools* that register **hook functions** at Netfilter's hooks and let you configure **rules**. They don't process packets themselves; they *configure the kernel* to. nftables is the modern successor to iptables (same Netfilter underneath, new syntax).
- **A rule** — your instruction: *"for packets matching X, do action Y."* This is what you add/remove with the `iptables` command.

Mental chain:

> Netfilter hook (checkpoint) → iptables hook function (interceptor registered there) → your rule (match + action) → the action runs when a packet matches.

## Hooks (the checkpoints)

A **hook** = a point in the packet's journey where the kernel calls any registered callback. A **hook function** = the callback a component (like iptables) registers there; the kernel calls it for every packet crossing that hook, and it returns a verdict (accept / drop / modify).

The five Netfilter hooks, in the order a packet may hit them:

- **PREROUTING** — just arrived, before any routing decision.
- **(Routing decision)** — "is this packet for *this* host, or passing through?"
- **INPUT** — packets destined *to this host*.
- **FORWARD** — packets *passing through* this host to elsewhere.
- **OUTPUT** — packets *generated by this host*.
- **POSTROUTING** — about to leave; the last step before egress.

## The two paths through the diagram

Every packet takes one of two routes (from *this host's* perspective):

- **Up-and-over (for/from this host):** `Prerouting → Routing → Input → Local Process → Routing → Output → Postrouting`. Traffic *to or from a process on this machine* (e.g. SSH into the host, or the host making its own request).
- **Straight across (through this host):** `Prerouting → Routing → Forward → Postrouting`. Traffic *passing through* — the host is a **relay**, not the recipient. Requires **IP forwarding** enabled.

Both routes converge at **POSTROUTING** before exiting — which is why POSTROUTING is where you rewrite the source of *any* outbound packet.

## Tables (what kind of work happens)

Rules live in **tables**, each hooking certain points:

- **nat** — address rewriting. DNAT (rewrite destination) at PREROUTING; SNAT / **masquerade** (rewrite source) at POSTROUTING.
- **filter** — allow / block (the firewall).
- **mangle**, **raw** — packet marking, connection-tracking exemptions (rarely needed).

## Masquerade

**Masquerade is an *action* (a rule *target*), not the hook function.**

- iptables registers *one* hook function at POSTROUTING (the interceptor).
- That function walks your rules; when a packet matches a rule whose action is `MASQUERADE`, it **rewrites the packet's source IP** to the outgoing interface's current IP.
- Masquerade = SNAT where the new source is "whatever the exit interface's IP is now" (vs. a fixed address) — convenient when the host IP may change.

Other targets the same hook function can apply: `ACCEPT`, `DROP`, `DNAT`, `SNAT`, etc. Masquerade is just one.
