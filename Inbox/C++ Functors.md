A **functor** (function object) is an object that **behaves like a function and carries its own data**. See also [[C++ Syntax]].

- **Data** → stored in member variables, set once when the object is constructed
- **Behavior** → defined in `operator()`, runs every time the object is called

---

## The problem it solves

STL algorithms like `std::count_if` call your predicate with **one argument** (the element):

```cpp
bool greaterThan10(int x) { return x > 10; }

std::vector<int> v = {5, 12, 8, 20, 15};
std::count_if(v.begin(), v.end(), greaterThan10); // 3
```

But what about "greater than N", with N chosen at runtime? You can't add a second parameter, and a plain function has nowhere to store N.

→ You need something that **remembers a value** *and* **can be called with one argument**: an object with `operator()`.

---

## Writing a functor

```cpp
struct GreaterThan {
    int limit;                      // remembered value

    bool operator()(int x) const {  // called with gt(x)
        return x > limit;
    }
};
```

```cpp
GreaterThan gt15{15};   // construction → limit = 15
gt15(20);               // true  (compiler runs gt15.operator()(20))
gt15(8);                // false

std::count_if(v.begin(), v.end(), GreaterThan{10}); // 3

int n;
std::cin >> n;
std::count_if(v.begin(), v.end(), GreaterThan{n});  // N chosen at runtime
```

The algorithm just writes `pred(element)`. It doesn't care whether `pred` is a function or a functor.

---

## Where does `limit` get its value?

`GreaterThan` has public members and no user-written constructor, so it's an **aggregate**: braces fill the members in declaration order.

```cpp
GreaterThan gt{15};   // limit = 15
```

That's equivalent to writing the constructor yourself:

```cpp
struct GreaterThan {
    int limit;
    GreaterThan(int l) : limit(l) {}
    bool operator()(int x) const { return x > limit; }
};
```

`limit` is **set once at construction** and only **read** by `operator()`. The `const` on `operator()` guarantees that calling the functor doesn't modify it.

### Stateful functor (modifies itself)

```cpp
struct Counter {
    int calls = 0;
    void operator()(int) { ++calls; }  // no const: modifies the object
};
```

---

## `operator()` is not a constructor

`operator` is the keyword for **operator overloading**: defining what `+`, `==`, `[]`, `()`… do for your class. `operator()` overloads the **call operator**.

| | Constructor | `operator()` |
|---|---|---|
| Name | Same as the class | `operator()` |
| Return type | None | Any |
| Runs | Once, when the object is **created** | Each time the object is **called** |

```cpp
GreaterThan gt{10};  // constructor
gt(5);               // operator()
gt(42);              // operator() again, same object
```

> [!tip] Why `operator()(int x)` has two pairs of parentheses: the first `()` is part of the name, the second holds the parameter list.

---

## Why use a functor instead of a function?

- **Holds state**: no globals or extra parameters needed
- **Has a type**: can be passed as a template parameter (`std::set<int, std::greater<int>>`, custom comparator for `std::map`)
- **Fast**: the compiler knows exactly which `operator()` runs, so it can inline it (a function pointer is usually an indirect call)

### Built-in functors (`<functional>`)

`std::plus`, `std::minus`, `std::less`, `std::greater`, `std::equal_to`…

```cpp
std::sort(v.begin(), v.end(), std::greater<int>()); // descending
```

## Functors and lambdas

A lambda is a **functor generated by the compiler**:

```cpp
int n = 15;
std::count_if(v.begin(), v.end(), [n](int x) { return x > n; });
```

That compiles to an unnamed class roughly equivalent to `GreaterThan`:
- capture list `[n]` → member variable
- lambda body → `operator()`

In modern C++ you use **lambdas** for one-off cases, and write a **named functor** when you need a reusable type (e.g. custom comparator for a `std::map` / `std::set`).

> [!note] In functional programming (Haskell, category theory), "functor" means something unrelated: a type you can `map` over.
